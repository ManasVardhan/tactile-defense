# Unit Squads Plan 2 (Units, Ladder, Levels) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the game loop on top of Plan 1: four more unit types with passive abilities, a ten-level ladder that unlocks units and squad slots, a squad builder, designed Levels 2 to 6, and a final regression and web build.

**Architecture:** Abilities are small components driven by `PlayerUnit` and configured by `UnitTypeConfig` flags. Progression is derived from the profile's existing `defeatedBases` list through one pure static class (`Progression`). The squad is a list of unit type ids in the profile, passed to the battle through `BattleLoadout`. Designed levels are hand-written `BaseLayoutData` in `ProgressionBuilder` in place of the seeded generator.

**Tech Stack:** Unity 6000.3.22f1, URP, C#, Unity Test Framework, existing `UI/Kit`.

**Spec:** `Docs/superpowers/specs/2026-11-24-unit-squads-hex-deploy-design.md` sections 5.5 (Healer, Sniper, Vanguard, Demolisher), 5.6, 5.7 (mercenary, research), 6, 6.1 (Levels 2 to 6), 7. Builds on `Docs/superpowers/plans/2026-11-24-unit-squads-plan-1-controls.md`.

- Values (starting points, relative to Attacker):

| Type | glyph | health | range | speed | damage | fire interval | other |
|---|---|---|---|---|---|---|---|
| Healer | H | 0.8 | n/a | 1 | n/a | n/a | `hasWeapon false`, `healPerSecond` = 12 percent of an Attacker soldier's max health, `reviveInterval 8` |
| Sniper | S | 0.6 | 2 | 1 | 3 | 3 | none |
| Vanguard | V | 1 | 1 | 2 | 0.6 | 1 | `captureWeight 2` |

**Behavior:**
- Healer soldiers never fire (`Soldier.HoldFire` or no weapon). Each tick the unit shares `healPerSecond * dt` among injured living friendly soldiers standing on its own hex or the six neighboring hexes (by the hex of the soldier's unit, and the mercenary later), most injured first, never above max health. Every `reviveInterval` seconds, if a unit on a neighboring hex has between 1 and `soldierCount - 1` living soldiers, one of its dead soldiers returns at 50 percent health at its slot (spawn a fresh soldier into that slot; the unit's `AliveCount` rises). Healers do not heal or revive their own unit's dead, and a destroyed unit stays destroyed. Healing shows a small visual on the healed soldier using an existing VFX from `VfxManager` tinted green.
- Sniper: only the config values; verify its shots really reach targets at twice the Attacker range (projectile lifetime scales with range).
- Vanguard: `CapturePoint` counts each Vanguard soldier as `captureWeight` toward its speed bonus.
- Demolisher: fires a lobbed shell at the target's position (reuse the cannon structure's lob, warning marker not required for player shells) that deals area damage with `UnitRegistry.DamageArea`, multiplied by `structureDamageMult` against `TargetKind.Structure` and `soldierDamageMult` against soldiers. When `prefersStructures`, it targets the nearest structure in range before any soldier.

- Test: `Assets/Tests/EditMode/ProgressionTests.cs`, extend `MetaTests.cs`; `Assets/Tests/PlayMode/LadderFlowTests.cs`

**Interfaces (namespace `TactileWars.Meta`):**
- `static class Progression`:
  - `const int LevelCount = 10;`
  - `static int LevelsCleared(PlayerProfile p, MetaDatabase db)`: the number of consecutive levels cleared starting at Level 1 (level N is base `db` roster index N - 1; a level counts when its id is in `p.defeatedBases`).
  - `static bool IsLevelOpen(int level, int cleared)` = `level <= cleared + 1`.
  - `static int SquadSlots(int cleared)` = `Mathf.Min(8, 3 + Mathf.Min(cleared, 5))`.
  - `static bool IsUnlocked(UnitTypeId id, int cleared)`: Attacker and Tank always; Healer at 1; Sniper at 2; Vanguard at 3; Demolisher at 4.
  - `static int UnlockLevel(UnitTypeId id)` (0 for the starters).
  - `static string RewardText(int level)`: what clearing that level grants, for example "Unlocks Healer, +1 squad slot" for level 1, "+1 squad slot" for level 5, empty for 6 to 10.
  - `static List<UnitTypeId> RepairSquad(IList<UnitTypeId> squad, int cleared)`: drops locked types, truncates to the slot count, pads empty slots with Attacker; result length equals `SquadSlots(cleared)`; a null or empty input gives Attacker, Attacker, Tank padded with Attackers.
- `PlayerProfile`: add `public List<int> squad` (unit type ids as ints). `MetaGame.Squad` returns the repaired squad; `MetaGame.SetSquadSlot(int index, UnitTypeId type)` and `MetaGame.ClearSquadSlot(int index)` (a cleared slot is stored as -1 and is skipped when building the loadout; at least one entry must remain, otherwise the call is refused).
- `BattleLoadout`: add `public List<UnitTypeId> squad;`. `LoadoutBuilder.Build` fills it from `MetaGame.Squad` (skipping cleared slots). `BattleSetup` calls `army.SetSquad(lo.squad)` in attack mode. A null `squad` keeps the army default.
- `MetaGame.IsBaseUnlocked(b)` becomes `Progression.IsLevelOpen(levelOf(b), LevelsCleared)`; `BaseDefinition.requiredLevel` is no longer consulted. `ApplyBattleResult` returns in `RewardSummary` a new `string unlockText` set only when the win raised `LevelsCleared` (first clear).

**Behavior:**
- Save migration (bump `SaveSystem.CurrentVersion`): an old save gets `squad` from `RepairSquad(null, cleared)`; gold spent on research nodes `squad_size` and `reinforcement_size` is refunded (sum of the costs of the levels bought, using the node's cost table) and those entries removed. Remove those two nodes from `ProgressionBuilder`; rename "Leader Training" to "Mercenary Training" with text saying it strengthens the hired mercenary.
- Mercenary: when the loadout has a mercenary, `PlayerArmy` gets one extra entry of a synthetic single-soldier type (`soldierCount 1`, glyph "M", health and damage from the mercenary loadout as `BattleSetup` computes today, model scale from the loadout) placed after the squad entries. It counts for `CanStillFight`, is skipped by `RestoreLastDestroyed`, can be healed, and is never revived.
- Attack screen: a vertical ladder of ten entries in level order. Each shows "Level N", the base name, a state (locked with a lock icon, open, cleared with a check), the enemy faction color and `Progression.RewardText(N)` when not empty. Only open or cleared entries have a Fight button. Replace the old lock text about player level.
- Army screen: `SquadBuilderPanel` above the mercenary roster. A row of `SquadSlots` slots showing glyph and name (or "Empty"), and a palette of all six types; locked types are greyed with "Level N" (their unlock level) and do nothing when clicked. Clicking an unlocked type fills the first empty slot (nothing happens when full). Clicking a filled slot clears it, unless it is the last filled one. Each palette item shows the type's `description` when hovered or selected. Exposes `IReadOnlyList<UIButton> SlotButtons`, `IReadOnlyList<UIButton> TypeButtons` for tests.
- Result screen: when `unlockText` is set, show it as a highlighted line ("Unlocked: Healer, +1 squad slot").
- When a slot is gained it arrives filled with an Attacker (follows from `RepairSquad`).
